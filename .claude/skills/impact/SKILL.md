# 변경 영향도 분석

`$ARGUMENTS` 의 첫 값은 수정하려는 함수 · 프로시저의 `파일:줄번호` 또는 이름, 둘째 값은 모듈 경로(선택)다. 첫 값이 없으면 묻는다.

- 코드는 고치지 않는다. `legacy/`, `modern/`, `db/`, `docs/` 의 파일은 읽기만 한다.
- 결과는 답변으로 보고한다. 파일을 만들거나 `docs/` 의 문서에 덧붙이지 않는다.
- 소스를 읽어서 추적한다. 화면이나 DB 를 실행하지 않았으면 답변 첫 줄에 그렇게 적는다.
- 모든 항목에 저장소 루트 기준 `파일:줄번호` 를 적는다. 근거 줄을 댈 수 없으면 "확인 필요"로 적는다.
- 긴 경로를 줄여 쓰려면 답변 첫머리에 줄임이 가리키는 폴더를 적는다(예: `L/` = `legacy/assignment-thymeleaf/src/main/java/com/example/assign/`).
- 커밋 전인 파일도 검색한다. `git grep` 은 추적되지 않은 파일을 건너뛰므로 `git grep --untracked` 나 Grep 을 쓴다. `docs/<모듈명>/` 이 아직 커밋되지 않았을 수 있다.

## 절차

### 1. 정의 위치

- `파일:줄번호` 를 받으면 그 줄을 읽고, 그 줄을 감싸는 함수 · 메서드 · 프로시저를 대상으로 삼는다.
- 이름을 받으면 정의를 검색한다. 정의가 여러 곳(다른 모듈, 오버로드, 같은 이름의 PHP 함수와 Java 메서드)에서
  나오면 후보를 `파일:줄번호` 로 나열하고 어느 것인지 묻는다.
- 요청이 모듈을 밝혔으면(둘째 인자, 또는 대화에서 지정한 모듈 경로) 그 모듈의 정의를 대상으로 삼고 묻지 않는다.
  나머지 후보는 "대상" 절에 `파일:줄번호` 로 적고, 고른 이유를 한 줄로 적는다.
- `클래스.메서드` 형식이어도 정의가 하나라고 가정하지 않는다. 레거시와 `modern/api` 에 같은 클래스 · 메서드 이름이 있다.
- 정의를 찾지 못하면 검색한 패턴을 적고 끝낸다. 비슷한 이름으로 대신 분석하지 않는다.

| 모듈 | 정의를 찾는 패턴 |
|---|---|
| `legacy/item-bank-php` | `function <이름>(` |
| `legacy/assignment-thymeleaf`, `modern/api` | 메서드 선언, 클래스 이름 |
| `legacy/grade-mssql` | `sql/` 의 `CREATE PROCEDURE` · `CREATE FUNCTION`, Java 호출부의 메서드 선언 |
| `modern/web` | `function <이름>`, `const <이름> =`, `export` |

### 2. 호출부 역추적

직접 호출 → 그 호출부를 부르는 곳 → 진입점 순으로 한 단계씩 올라간다. 단계마다 호출 줄을 읽어서 확인한다.

| 모듈 | 호출부 | 진입점(화면 · URL) |
|---|---|---|
| `legacy/item-bank-php` | 함수 호출 줄, 그 파일을 `require` · `include` 하는 파일 | 최상위 `*.php` = 8081 의 URL |
| `legacy/assignment-thymeleaf` | 메서드 호출 줄, 주입받는 클래스 | `@RequestMapping` 계열 매핑 = 8082 의 URL, 반환하는 뷰 이름의 템플릿 = 화면. 그 URL 을 가리키는 `th:action` · `th:href` 도 찾는다 |
| `legacy/grade-mssql` | 다른 프로시저의 `EXEC`, Java 의 `{call …}` · `EXEC …` 문자열 | Java 호출부의 매핑 = 8083 의 URL |
| `modern/api` | 메서드 호출 줄, 주입받는 클래스 | 컨트롤러 매핑 = 8080 의 URL |
| `modern/web` | 컨트롤러 경로를 부르는 `src/api/*.ts` → `src/hooks/use*.ts` → 컴포넌트 | 컴포넌트를 그리는 화면 |

- `modern/api` 의 엔드포인트가 경로에 있으면 `modern/web` 까지 이어서 추적한다.
- 멈추는 조건은 둘이다. 진입점에 닿았거나, 더 위의 호출부가 검색되지 않았거나. 경로마다 어느 쪽인지 적는다.
- 호출부가 검색되지 않은 것을 "호출부 없음"으로 단정하지 않는다. 검색한 패턴과 범위를 적고 "추적 한계"에 올린다.
- 테스트 코드의 호출은 호출 경로에 넣지 않고 5번 "기존 테스트"에 적는다.

### 3. 테이블

1. 대상 함수와, 대상 함수가 부르는 함수가 실행하는 SQL 에서 테이블 · 뷰를 찾는다.
   `FROM` · `JOIN` 은 읽기, `INSERT INTO` · `UPDATE` · `DELETE FROM` 은 쓰기다.
   JPA 는 엔티티의 `@Table`, 리포지토리의 `@Query` · 메서드 이름 쿼리로 찾는다.
2. 뷰를 읽으면 `db/*/init/` 의 뷰 정의를 읽어 원본 테이블까지 적는다. 모듈 폴더 밖이라는 이유로 건너뛰지 않는다.
3. 찾은 테이블 이름을 `legacy/`, `modern/`, `db/` 전체에서 검색해 같은 테이블을 쓰는 다른 함수를 찾는다.
   문항 은행 · 과제 배포 · `modern/api` 는 `itembank` 스키마를 공유하므로 다른 모듈도 빼지 않는다.
4. 함수마다 읽기 / 쓰기를 구분한다. 대상 함수가 쓰는 테이블을 읽는 함수를 먼저 적는다.
5. JPA 의 쓰기는 SQL 문자열 검색으로 나오지 않는다. `@Table` 엔티티에서 필드 값을 바꾸는 메서드를 찾고,
   그 메서드를 `@Transactional` 안에서 부르는 곳을 쓰기로 적는다.
6. 다른 함수가 같은 테이블에 쓰면 바꾸는 컬럼을 적는다. 대상 함수와 바꾸는 컬럼이 다르면 그 차이를 적는다.

### 4. 비즈니스 규칙

- 대상 모듈의 `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽는다. 없으면 "규칙 문서 없음"이라고 적고 넘어간다.

| 모듈 경로 | 모듈명 |
|---|---|
| `legacy/item-bank-php` | `item-bank` |
| `legacy/assignment-thymeleaf` | `assignment` |
| `legacy/grade-mssql` | `grade` |

- 규칙의 "근거" 줄이 대상 함수 또는 호출 경로 위 함수의 줄 범위 안에 있으면 관련 규칙이다.
  낱말이 비슷하다는 이유만으로 연결하지 않는다.
- 3번에서 찾은 테이블을 근거로 하는 규칙도 연결하고, 연결 이유를 "함수" / "테이블"로 구분한다.
- 규칙 ID 는 문서에 적힌 그대로 옮긴다. 보고 전에 ID 와 규칙 문장을 문서와 다시 대조한다.
- 관련 규칙이 10개를 넘으면 연속한 ID 를 범위(`BR-18 ~ BR-53`)로 묶어 한 행에 적어도 된다.
  범위 안의 모든 ID 가 같은 연결 이유에 해당하는지 확인하고, "규칙" 칸에는 범위가 다루는 주제를 적는다.
- 대상이 `modern/` 이면 이관 원본인 레거시 모듈의 규칙 문서를 본다. 원본을 특정할 수 없으면 "확인 필요"로 적는다.

### 5. 테스트 케이스

1. 기존 테스트를 먼저 찾는다. 대상 함수와 진입점을 다루는 `characterization/` 의 스냅샷 · 테스트,
   각 모듈의 `src/test`, `modern/web` 의 `*.test.ts(x)` 가 대상이다.
2. 기존 테스트가 다루지 않는 것을 제안한다. 제안마다 관련 규칙 ID 또는 진입점을 붙인다.
3. 입력 분기는 빈 문자열 · `0` · 음수 · 숫자가 아닌 값을 각각 나눠서 제안한다.
4. 정렬 · 행 순서 · 태그 순서를 바꿀 수 있는 수정이면 `characterization/` 스냅샷이 깨질 수 있다고 적는다.
5. 이름이 같은 다른 모듈 함수의 테스트는 기존 테스트로 세지 않는다. 따로 적고 다른 함수의 테스트라고 밝힌다.
6. 경계값은 기준의 바로 아래 · 같음 · 바로 위를 각각 제안한다. 분기마다 한 행 이상을 둔다.

## 출력 형식

아래 순서를 바꾸지 않는다. 해당 사항이 없는 절은 지우지 않고 "없음"이라고 적는다.

### 대상

- 함수 · 프로시저 이름, 정의 위치(`파일:줄번호`), 모듈, 실행 여부(소스만 읽음 / 실행함)
- 같은 이름의 다른 정의: `파일:줄번호` 와 고르지 않은 이유. 없으면 "없음"

### 영향받는 화면

| 화면 · URL | 모듈 | 근거 |
|---|---|---|
| `GET /search.php` | `legacy/item-bank-php` | `legacy/item-bank-php/search.php:<줄번호>` |

### 호출 경로

진입점에서 대상 함수 방향으로 적는다. 경로 하나가 한 줄이고, 단계마다 호출 줄을 붙인다.

```
<진입점 URL · 화면> (<파일>:<줄번호>)
  → <중간 함수>() (<호출 줄의 파일>:<줄번호>)
  → <대상 함수>() (<호출 줄의 파일>:<줄번호>)   ← 대상
```

- 진입점에 닿지 못한 경로는 끝에 "(진입점 미확인)"을 붙인다.

### 영향받는 테이블

| 테이블 · 뷰 | 대상 함수의 접근 | 근거 | 같은 테이블을 쓰는 다른 함수 (읽기 / 쓰기, 근거) |
|---|---|---|---|

### 관련 규칙 ID

| 규칙 ID | 규칙 | 연결 이유 | 근거 |
|---|---|---|---|
| BR-01 | <문서의 규칙 문장> | 함수 | `docs/item-bank/BUSINESS-RULES.md:<줄번호>` |

### 수정 전에 확보해야 할 테스트 케이스

- 기존 테스트: 파일:줄번호 와 무엇을 검증하는지
- 제안:

| # | 입력 · 상황 | 기대 결과 | 관련 규칙 ID · 진입점 | 근거 |
|---|---|---|---|---|

### 추적 한계

검색으로 찾지 못하는 경로가 의심되는 곳이다. 위 절에 섞지 않고 여기에만 적는다.

| 의심 위치 | 유형 | 확인하지 못한 것 | 사람이 확인할 방법 |
|---|---|---|---|

아래에 해당하면 올린다.

- PHP: 가변 함수(`$fn()`), `call_user_func`, 변수로 만든 `include` · `require` 경로
- Java: 리플렉션, 문자열을 이어 붙여 만든 SQL · 프로시저 이름, 설정 파일 · 스케줄러로 등록된 호출
- MS-SQL: `sp_executesql`, `EXEC(@sql)` 같은 동적 SQL, 트리거, 저장소에 정의가 없는 프로시저
- 템플릿 · 화면: `${…}` 로 조립한 URL, 문자열을 이어 붙인 API 경로
- 저장소 밖 호출자(배치, 다른 시스템, DB 작업 스케줄)
- 화면의 표시 조건(`th:if`, `disabled`)으로만 막은 경로: URL 을 직접 호출하면 닿는 분기
- 같은 테이블에 쓰는 다른 모듈과의 동시 갱신, 표준 출력 · 로그를 읽는 저장소 밖 수집기
- 실행 옵션 · 시스템 속성 · 드라이버 설정이 결과를 바꾸는 곳

## 하지 말 것

- 읽지 않은 호출 줄을 경로에 넣지 않는다. 검색 결과만 보고 적지 않고, 그 줄을 읽어서 호출인지 확인한다.
  주석 · 문자열 안의 일치는 호출로 세지 않는다.
- 호출 방향을 뒤집어 적지 않는다. 존재하지 않는 함수 · 파일 · 규칙 ID 를 적지 않는다.
- 이름이 같은 다른 함수의 호출부를 섞지 않는다. 클래스 · 파일 · `require` 관계로 같은 함수인지 확인한다.
- 실행하지 않은 동작을 확인한 것처럼 적지 않는다. 콜레이션 · 정렬 순서 · 제약 위반처럼 DB 가 결정하는 것은
  "추적 한계"에 넣는다.
- 수정 방법을 제안하거나 코드를 고치지 않는다. 영향 범위와 테스트 케이스 제안까지만 보고한다.
