# RCA 리포트 마스킹 규칙

리포트를 저장하기 전에 아래 규칙을 본문 · 표 · 원문 발췌 · 명령 출력 전체에 적용한다.

| 대상 | 처리 | 예 |
|---|---|---|
| IP 주소 | 구분이 필요하면 역할 별칭으로 바꾼다. 구분이 필요 없으면 `<IP>` 로 바꾼다 | `API-1:8080`, `교사단말A`, `<IP>` |
| 이메일 | `<EMAIL>` 로 바꾼다 | `<EMAIL>` |
| 학생 식별자(`STU-…`) | 등장 순서대로 학생A, 학생B … 로 바꾼다 | `학생A` |
| 토큰 · 세션 ID · API 키 | `<TOKEN>` 으로 바꾼다. 앞뒤 일부도 남기지 않는다 | `Bearer <TOKEN>` |
| 비밀번호 · 접속 문자열 | 비밀번호와 계정이 들어간 접속 문자열을 `<SECRET>` 으로 바꾼다 | `jdbc:mariadb://<SECRET>` |

## 역할 별칭

- 서버는 역할과 번호로 부른다: API-1, API-2, DB-1, LB-1 …
- 클라이언트는 역할과 순서 문자로 부른다: 교사단말A, 교사단말B … (학생 단말이면 학생단말A …)
- 번호 · 문자는 리포트 안에서 처음 등장한 순서대로 붙인다. 같은 값은 리포트 전체에서 같은 별칭을 쓴다.
- 별칭은 원래 값을 짐작할 수 있는 정보(대역 · 끝자리 · 호스트명 일부)를 담지 않는다.

## 적용 방법

- 대응표는 작업 중 대화 안에서만 쓴다. 파일로 남기지 않는다.
- 마스킹 전 원본을 다른 위치에 복사하지 않는다. 원본 로그는 수정하지 않는다.
- 저장 후 리포트에서 IP · 이메일 · `STU-` · `Bearer` · `password` 패턴을 다시 검색해 남은 값이 없는지 확인한다.
- 리포트 맨 끝에 다음 형식으로 건수를 적는다.

```
마스킹 적용: IP 주소 N건 · 이메일 N건 · 학생 식별자 N건 · 토큰 N건 · 비밀번호/접속 문자열 N건
```
