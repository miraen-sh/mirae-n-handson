# 승인 체크리스트 v1

v1 · 2회차
- 네 기준의 판정선을 팀 결정으로 정했다: public 메서드 테스트 필수, 치명 4종, 범위 밖은 import 정리만, 컨벤션 반려 3종 + 네이밍 경고.
- 리뷰어 판단에 맡기던 항목을 모두 예/아니오로 답하는 문장으로 바꿨다.
- 경고는 승인을 막지 않는다. 반려 사유는 네 기준 항목의 "아니오"와 치명 이슈뿐이다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준의 반려 항목이 **모두** "예"여야 승인이다. 하나라도 "아니오"면 반려.
판단할 근거가 없어 예/아니오를 정할 수 없는 항목은 "확인 필요"로 적고, 그 항목이 남아 있는 동안은 승인하지 않는다.

## 심각도 정의

- **치명** — 아래 네 가지 중 하나. 1건이라도 있으면 반려.
  - 비밀값 노출: 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처 · 로그에 들어간다.
  - 데이터 손실: 요청 문장에 없는 삭제 · 덮어쓰기가 생긴다.
  - 인증 우회: 인증 · 권한 검사를 없애거나 건너뛴다.
  - SQL 문자열 조립: SQL 을 문자열 이어 붙이기 · 포맷으로 만든다.
- **경고** — 네 기준의 반려 항목을 어기지는 않았지만 고쳐야 하는 문제(예: 네이밍 규칙 위반). 승인을 막지 않는다. 이슈 목록에 남기고 후속 수정을 요청한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류(컴파일 오류 포함)가 0건이다.
- [ ] diff 에서 새로 생기거나 시그니처가 바뀐 public 메서드마다 그 메서드를 호출하는 테스트가 1개 이상 있다. 컨트롤러 핸들러 메서드도 포함한다. 생성자와 record 가 자동으로 만드는 접근자는 제외한다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처 · 로그 문구에 리터럴로 들어 있지 않다(실습용 더미 `app-pass` 는 예외).
- [ ] 데이터를 지우거나 덮어쓰는 코드(DELETE · UPDATE · truncate · 기존 행을 덮어쓰는 save)가 새로 생겼다면 요청 문장에 그 내용이 들어 있다.
- [ ] 인증 · 권한 검사를 없애거나 건너뛰는 변경(검사 코드 삭제, `permitAll` 추가, 특정 값이면 통과시키는 조건)이 없다.
- [ ] SQL 을 문자열로 이어 붙이거나 포맷해 만드는 곳이 없다(파라미터 바인딩 사용).

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 문장으로 설명되지 않는 변경 줄은 모두, 요청 때문에 고친 파일 안의 import 정리다(메서드 추출 · 이름 변경 · 로그 문구 변경 · 포맷팅은 해당하지 않는다).
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청 문장에 들어 있다.

## 4. 컨벤션 준수

컨벤션 기준은 팀 `CLAUDE.md` 다. 저장소 루트에 없으면 `templates/CLAUDE.spring.md` 로 대조하고, 그 사실을 판정에 적는다(`convention-check` Skill 이 있으면 그 결과를 쓴다).

반려 항목 — 하나라도 "아니오"면 미충족.

- [ ] 계층 규칙을 어긴 곳이 없다: 컨트롤러가 Repository 를 주입받거나 SQL 을 실행하지 않고, 서비스가 다른 도메인의 Repository 를 직접 주입하지 않는다(`CLAUDE.spring.md:21-23`).
- [ ] 예외를 잡고 아무 처리 없이 넘기는 빈 `catch` 블록이 없다.
- [ ] `System.out` · `System.err` · `printStackTrace()` 호출이 없다.

경고 항목 — "아니오"여도 미충족이 아니다. 위반 한 건마다 경고 이슈로 적는다.

- [ ] 클래스 · 메서드 · 필드 · 상수 · 테스트 메서드 이름이 네이밍 규칙(`CLAUDE.spring.md:39,43`)을 따른다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
